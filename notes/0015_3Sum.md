# 0015 3Sum

## Problem Idea

We are given an integer array `nums`.

We need to find all unique triplets:

- `[nums[i], nums[left], nums[right]]`

such that:

- `nums[i] + nums[left] + nums[right] == 0`

Important detail:

- the answer cannot contain duplicate triplets

Example:

- `nums = [-1, 0, 1, 2, -1, -4]`
- valid answers are `[-1, -1, 2]` and `[-1, 0, 1]`

This problem is a classic combination of:

- sorting
- fixing one number
- using two pointers for the remaining two numbers

---

## My Code Notes

```python
nums.sort()
res = []
n = len(nums)

for i in range(n - 2):
    if i > 0 and nums[i] == nums[i - 1]:
        continue

    left, right = i + 1, n - 1

    while left < right:
        total = nums[i] + nums[left] + nums[right]

        if total < 0:
            left += 1
        elif total > 0:
            right -= 1
        else:
            res.append([nums[i], nums[left], nums[right]])
            left += 1
            right -= 1

            while left < right and nums[left] == nums[left - 1]:
                left += 1
            while left < right and nums[right] == nums[right + 1]:
                right -= 1

return res
```

What this code does:

- Sort the array first.
- Fix one value using index `i`.
- Use `left` and `right` to search for the other two numbers.
- Compare the current sum with `0`.
- Move pointers inward depending on whether the sum is too small or too large.
- Skip duplicates so the final result only contains unique triplets.

---

## Why Sorting Helps

After sorting:

- smaller values are on the left
- larger values are on the right

That means for a fixed `nums[i]`:

- if the current sum is too small, we should move `left` to the right
- if the current sum is too large, we should move `right` to the left

This is the same core idea as the standard two-pointer pattern on a sorted array.

Without sorting, we would not know which pointer movement makes the sum larger or smaller.

---

## Why We Skip Duplicates

There are two places where duplicates matter.

### 1. Skip duplicate starting values

```python
if i > 0 and nums[i] == nums[i - 1]:
    continue
```

If the current `nums[i]` is the same as the previous one, it would generate the same triplets again.

---

### 2. Skip duplicate `left` and `right` values after finding a match

```python
while left < right and nums[left] == nums[left - 1]:
    left += 1
while left < right and nums[right] == nums[right + 1]:
    right -= 1
```

After adding one valid triplet:

- move both pointers once
- then keep moving while the values are repeated

This prevents repeated triplets like:

- `[-1, 0, 1]`
- `[-1, 0, 1]`

from being added multiple times.

---

## Small Example

For:

- `nums = [-1, 0, 1, 2, -1, -4]`

After sorting:

- `[-4, -1, -1, 0, 1, 2]`

Try `i = 0`:

- fixed value = `-4`
- search for two numbers whose sum is `4`
- no valid triplet is found

Try `i = 1`:

- fixed value = `-1`
- `left = 2`, `right = 5`
- sum = `-1 + -1 + 2 = 0`
- add `[-1, -1, 2]`

Continue:

- move both pointers
- now check `-1 + 0 + 1 = 0`
- add `[-1, 0, 1]`

These are the unique answers.

---

## Complexity

- Time: `O(n^2)`
- Space: `O(1)` extra space, not counting the output

Why:

- sorting costs `O(n log n)`
- the outer loop runs `n` times
- the inner two-pointer scan is linear for each fixed `i`
- overall this becomes `O(n^2)`

---

## Key Learning

- `3Sum` is often solved by reducing it into many `2Sum`-style searches.
- Sorting is what makes the two-pointer approach possible.
- Duplicate handling is a core part of the problem.
- When the problem asks for unique combinations, always think carefully about where duplicates can appear.
